# 仓库解析 CSV 契约

文件名推荐：`repo-resolution.csv`

## 必需列

- `服务名称`
- `命名空间`
- `业务归属`
- `编程语言`
- `运行环境`
- `包含正式环境`
- `仓库检索词`
- `匹配状态`
- `匹配仓库名`
- `匹配仓库地址`
- `候选仓库地址`
- `置信度`
- `人工确认仓库名`
- `人工确认仓库地址`
- `本地仓库路径`
- `备注`

## 状态枚举

### `匹配状态`

- `自动匹配`
  - 仓库名与服务名完全同名，系统自动确认
- `待确认`
  - 找到候选，但没有唯一完全同名仓库，需要人工确认
- `未找到`
  - 没找到足够可信的候选
- `已跳过`
  - 用户要求跳过，或该服务本轮不处理

### `置信度`

- `高`
- `中`
- `低`
- `无`

## 人工修订规则

人工修订时建议只改这些列：

- `人工确认仓库名`
- `人工确认仓库地址`
- `备注`

`编程语言` 默认来自飞书 Base 透传，通常不建议人工改写；若确需修正，优先回到飞书源头修复。
`运行环境` 与 `包含正式环境` 也默认来自飞书 Base 透传，通常不建议在 CSV 中手工改写；若源数据有误，优先回到飞书修复。

后续第二阶段优先读取：

1. `人工确认仓库地址`
2. 否则读取 `匹配仓库地址`，但前提是 `匹配状态 = 自动匹配`

## 候选格式

`候选仓库地址` 使用一个单元格保存多个候选，分隔符统一为：

```text
url1 | url2 | url3
```

不要使用换行或 JSON 数组。

## 复用规则

如果 CSV 已存在：

- 保留已有 `人工确认仓库地址`
- 不要覆盖用户手工填写内容
- 可以补写空白列，例如新增的 `编程语言`
- 可以更新 `候选仓库地址` 和 `备注`
- 除非用户明确要求重建，否则不要删除旧行

## 唯一键

默认以 `服务名称 + 命名空间` 作为一行服务实例的唯一标识。
