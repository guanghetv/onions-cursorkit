前端页面质量排查

对指定的前端页面文件进行九个维度的 UX 质量审查，输出结构化的问题待优化列表。

执行流程

1. 读取用户指定的页面文件（通常是 .vue 文件）
2. 逐项检查以下九个维度
3. 将排查报告写入与页面同目录、同名的 _check.md 文件中
  - 例如：views/detail/index.vue → views/detail/index_check.md
  - 例如：views/home.vue → views/home_check.md
  - 使用 Write 工具将报告内容写入该文件
审查维度

1. 加载视觉稳定性

检查是否存在布局跳动（CLS）风险：

- <img> 是否指定了宽高或使用 CSS aspect-ratio
- 动态内容区域（v-if 切换、异步加载内容）是否设置了 min-height 或占位容器
- 列表渲染是否会导致容器高度突变
- 字体加载是否可能导致文本重排
关注模式：

v-if="asyncData"          → 可能导致布局跳动，考虑 v-show 或骨架屏
<img> 无 width/height      → 图片加载后撑开容器
动态列表无固定高度容器     → 数据加载后页面跳动

2. 骨架屏和占位符

检查页面是否在数据加载期间提供即时视觉反馈：

- 页面初始加载时是否有骨架屏或 loading 状态
- 关键内容区域是否有加载态占位
- 是否存在长时间白屏场景（接口慢、数据量大）
- 下拉刷新/上拉加载是否有加载指示器
关注模式：

created/mounted 中请求数据但模板无 loading 判断   → 白屏风险
v-if="list.length" 且无空状态/加载态             → 加载期间区域消失
异步组件未配置 loading 组件                       → 组件加载期白屏

3. 错误处理

检查接口调用和代码异常是否有友好的用户反馈：

- API 请求是否有 catch 或 .then 的错误分支处理
- 错误发生时是否向用户展示了反馈（toast、错误状态页、重试按钮）
- async/await 是否包裹在 try/catch 中
- Promise 链是否遗漏了 .catch
- 网络异常、超时是否有处理
关注模式：

await apiCall() 无 try/catch                  → 异常无处理
.then() 无 .catch()                           → Promise 错误被吞
catch 块为空或仅 console.log                   → 用户无感知
接口失败后 UI 状态未重置（如 loading 未关闭）    → UI 卡死

4. 物理返回键与弹框交互

在 App 内 WebView 中，检查物理返回键是否正确处理弹框关闭：

- 页面中的弹框/模态框（Modal、Dialog、Popup、ActionSheet）打开时，返回键应关闭弹框而非退出页面
- 是否使用了 backStack、popstate 事件或类似机制管理弹框层级
- 多层弹框嵌套时是否支持逐层关闭
- 全屏遮罩/抽屉/底部面板等是否纳入返回键管理
关注模式：

OIModal/Dialog 组件未注册 backStack          → 返回键直接退出页面
弹框 visible 变化未与 history state 同步     → 返回键行为不一致
多个弹框同时存在但无层级管理                  → 返回键关闭顺序混乱

5. 图片容错

检查图片加载失败时是否有降级处理：

- <img> 是否绑定了 @error 事件处理
- 图片加载失败后是否显示占位图或重试操作
- 头像、封面等关键图片是否有 fallback
- 图片 CDN 链接拼接是否有防空处理（src 为空或 undefined）
- 长列表中的图片是否使用了懒加载
关注模式：

<img :src="url"> 无 @error                    → 加载失败显示裂图
:src="data.img" 且 data.img 可能为空          → src 为空白
无默认头像/封面兜底                            → 数据缺失时无图可显示

6. 按钮防抖与节流

检查用户交互操作是否有频率控制：

- 提交类按钮（发布、点赞、关注、删除）是否有防抖处理
- 按钮在异步操作期间是否 disabled 或显示 loading
- 滚动事件监听是否使用了节流
- 频繁触发的事件（input、resize、scroll）是否有节流/防抖
关注模式：

@click="submitForm" 无 debounce 包裹           → 重复提交
异步操作期间按钮仍可点击                        → 重复请求
scroll/resize 事件直接绑定无节流                → 性能问题
搜索输入无 debounce                            → 频繁请求

7. 动画和过渡

检查页面状态变化是否平滑自然：

- 弹框/抽屉的显示隐藏是否使用了 <transition> 或 CSS 过渡
- 列表项的增删是否使用了 <transition-group>
- 页面跳转/路由切换是否有过渡动画
- 展开/折叠操作是否有高度过渡
- 动画是否使用了 GPU 加速属性（transform、opacity）而非触发重排的属性（top、left、width、height）
关注模式：

v-if/v-show 控制的浮层无 <transition>          → 突然出现/消失
列表增删无动画                                  → 视觉突兀
CSS 动画使用 top/left 而非 transform           → 卡顿风险
过渡时长过长(>500ms)或过短(<100ms)              → 体验不自然

8. 顶部与底部安全距离

检查页面是否正确适配刘海屏、底部 Home Indicator 等异形屏安全区域：

- 顶部导航栏是否使用 safe-area-inset-top（CSS env / constant）或等效的 CSS 变量（如 --safe-area-top）做顶部偏移
- 底部固定栏（操作栏、输入框、Tab 栏）是否使用 safe-area-inset-bottom 做底部留白
- position: fixed 的元素是否考虑了安全距离
- 全屏弹框 / 遮罩是否覆盖安全区但内容不被遮挡
关注模式：

padding-top 硬编码固定值而非 safe-area       → 刘海屏被遮挡或留白不足
底部固定栏无 padding-bottom: env(safe-area-inset-bottom) → 内容被 Home Indicator 遮挡
fixed 定位元素 bottom: 0 无安全距离补偿       → 底部按钮/输入框被遮挡
height: 100vh 未配合 safe-area               → 页面底部内容超出可视区

9. 图片尺寸适配

检查图片是否根据显示尺寸请求了合适的资源大小，避免浪费带宽或显示模糊：

- 列表缩略图、头像等小尺寸展示位是否使用了 CDN 裁剪/缩放参数（如 squareW()、equalW() 或 URL 拼接 ?w=xxx）请求合适尺寸
- 大图预览场景是否加载了原图或高清尺寸
- 是否存在小容器加载大图（如 40px 头像加载 1000px 原图）
- 是否存在大容器使用小图导致模糊（如全屏预览使用缩略图）
- 不同 DPR 设备是否考虑了 2x/3x 适配
关注模式：

<img :src="url"> 无任何 CDN 尺寸参数           → 始终加载原图，浪费带宽
头像/缩略图未使用 squareW/equalW 裁剪          → 小容器加载大图
大图预览使用了裁剪后的缩略图 URL               → 放大后模糊
固定使用 2x 尺寸未考虑设备 DPR                → 低端设备多加载、高端设备不够清晰

等级

定义

注意事项

- 仅报告在当前文件中可观察到的问题，不推测外部组件的内部实现

- 关注实际影响，避免过度报告不影响体验的细节
