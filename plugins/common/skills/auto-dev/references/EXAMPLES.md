# 使用示例

## 单项目命中示例

输入：
`/auto-dev 修复登录页“验证码已发送”提示文案 https://project.feishu.cn/xxx/detail/123456`

输出：
- 先拉取飞书卡片详情并补全需求上下文
- 命中 1 个项目并展示证据
- 人工确认后：阶段A 在仓库中创建并推送 feature 分支
- 阶段B 由本机 `agent -p --force` 无头完成改码、CR、提交与 MR
- 最终 1 个指向 `develop` 的 MR 与完成通知

## 多项目命中示例

输入：
`/auto-dev 更新活动弹窗提示语 https://project.feishu.cn/xxx/detail/888999`

输出：
- 命中 3 个项目并展示证据
- 人工确认后：各仓阶段A 建同名分支；阶段B CLI 顺序处理 3 个仓
- 最终 3 个 MR 链接与完成通知

## 零命中阻断示例

输入：
`/auto-dev 优化某个未知模块 https://project.feishu.cn/xxx/detail/777666`

输出：
- 扫描结果命中 0 个项目
- 流程阻断，不做代码改动
- 提示补充关键词或手动指定项目

## 缺少飞书卡片链接示例（允许分支名兜底）

输入：
`/auto-dev 调整登录提示文案 branch=feat/2026-login-copy-fix`

输出：
- 识别到未提供飞书卡片链接，但提供了明确分支名
- 允许继续执行扫描与后续流程

## 缺少飞书卡片链接且无分支名示例（强制中断）

输入：
`/auto-dev 调整登录提示文案`

输出：
- 输入门禁失败，流程立即中断
- 提示“请提供飞书卡片链接，或明确开发分支名称后重试”

## CR 3 轮失败示例

输出：
- 第 1-3 轮持续存在 `Critical`
- 流程进入 `BLOCKED`
- 通知人工接管并附带恢复建议
