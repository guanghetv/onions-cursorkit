# 产品接入说明

交付版本：1.1.1｜2026-09-09  
依据：[业务风险评估框架 V4-9.4](https://guanghe.feishu.cn/docx/LlQldNdLpoatWWx4QOMcSoa8nod)，规则内容历史来源revision 227；本次B端编号按用户授权对齐revision 241正文。  
范围：37条R-*（31条业务、6条治理），27条G-*仅作证据参考。

## 先看一个例子

模拟需求写“新用户领取10天会员”，会触发R-免费活动-04，工作台显示“需调整”，并直接展示规则编号、名称、等级、原文、判定依据及整改要求。产品记录业务选择：改成7天后提交新版本重检；坚持10天则记录理由，询问是否需要制作例外评估申请包。已要求制作或提交例外评估时直接生成，不重复询问。生成后提供申请包链接，并指引提交“法务助理机器人-业务灰产风险损失评估”。双周汇总仍保留原10天方案的命中记录，并展示后续处理结果。其他规则同时检查，不能仅因天数改成7天就宣称整个需求通过。

## 文件用途

| 文件 | 用途 |
|---|---|
| SKILL.md | 工作台智能体入口、运行流程和权限边界 |
| references/rules.json | 37条原文规则、场景、等级、版本和结构化检查项 |
| references/input-output.md | 必要输入、条件字段、证据、计算语义、结果及法务交接 |
| references/biweekly.md | 逐次落库、周期、去重、指标、全量明细和异常补跑 |
| references/acceptance.md | 产品验收场景和预期行为 |

| agents/openai.yaml | 支持该元数据的智能体平台可使用的名称和调用提示 |

Skill无需依赖交付者本地目录或个人飞书CLI。整体复制product-requirement-risk-gate文件夹至工作台技能目录，并保留相对路径。若平台不支持文件型Skill，由产品将SKILL.md及其引用资源挂载到同一智能体知识资源，并确保每次按路由读取实际规则文件。

## 平台工程接入能力（不属于业务填报或当前预检条件）

1. 需求提交/版本变更事件：传入业务方案正文和已有元数据；完整PRD、产品负责人或平台ID不是业务结论必填。
2. 规则包加载：加载已发布且校验通过的规则版本；按input-output.md先区分业务必填与后置项，再编译eq/lte和多条件判定；DEFERRED不阻塞业务结论，使用完整37条扫描结果生成正式结论。AI抽取结果保留证据，语义不明确时人工核实。
3. 持久保存：需求快照、逐次检查、逐规则命中、业务反馈和状态事件；支持幂等写入及回读。
4. 页面交互：正文为结论、需处理事项、下一步及必要的业务回复；命中规则编号、名称、等级、原文、依据及整改必显。完整37条检查与审计信息进入详情，非必填技术信息标DEFERRED，不在业务预检向产品或研发索取。提供“接受整改”“不接受整改/申请例外”，不把接受整改当作已完成。
5. 法务交接：业务拒绝整改后先询问是否制作申请包；已有明确要求时直接制作。生成后提供链接并指引提交“法务助理机器人-业务灰产风险损失评估”。对接移交接口及接收状态；未接通时支持导出包人工交接，不宣称已发送。损失计算与审批依原框架在法务流程执行，L0保持D/专项路径。
6. 技术评审与发布流程：保存待核验控制、实际证据、审批/凭证和版本有效性；预检结果不能直接设置发布通过。
7. 双周服务器定时任务：按产品迭代起点每14天汇总并保存；支持运行日志、覆盖核验、失败补跑。
8. 数据访问：按业务/产品/技术/法务/规则发布职责配置权限，保留审计。可按需接入固定飞书Base同步。

上述为接入要求，本包未连接实际工作台、未部署数据库、未启用定时任务，亦未包含工作台API实现或现成规则执行服务。rules.json是结构化规则定义，产品须接入确定性执行器后才能承担正式门禁。可直接移交产品开展接入，不应把导入文件等同于上线验收。

## 分阶段验收

先用免费/低价权益活动跑通一条“提交→命中→整改/拒绝→记录→双周汇总”的完整链路，同时加载全部规则并检查多场景命中。其余场景按验收集接入。尚未接通的平台能力须显式标记未完成；非必填技术字段标DEFERRED而非业务待补，不能对全量需求宣布正式门禁已生效。

本次v1.1.1仅将B端旧02/03/04对应调整为当前01/02/03，规则内容、等级、检查条件和业务预检语义保持不变。历史快照及旧记录不改写；跨版本采用rules.json的rule_id_migrations，版本+编号联合识别。线上编号说明仍与正文矛盾，本次依用户明确要求采用正文编号，未修改线上框架，未发布工作台。空白仍区分missing/unavailable，详见输入输出协议。

规则更新经责任人确认和版本发布后生效，升级需保留旧版本回放；不根据飞书文档刚被编辑就静默改变线上判定。
