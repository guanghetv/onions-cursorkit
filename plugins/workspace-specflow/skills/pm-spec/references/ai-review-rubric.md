# PRD AI Review Rubric

用于 `/pm-spec` 的 AI 评审标准：高风险阻断 + 评分反馈 + 可定位改进建议。

落盘分层：

- 详细评审记录（评分、维度说明、定位问题项、改进建议）写入 `prototypes/ai-review.md`
- `prd.md` 仅保留“可开工结论”

## 一、评审范围（先于阻断规则执行）

读取 `## 开发速览` 中的 **需求类型** 与 **影响范围**，决定深审/轻审范围。

> **注意**：MODULE 标题的 `[新增/修改]` 仅表示**本次 PRD 中的变更模块**，不等于「增量/存量需求」。评审范围由需求类型决定，不由 MODULE 标签决定。

| 需求类型 | 评审模式 | 深审范围 | 轻审/降级 |
|----------|----------|----------|-----------|
| **新增** | 全量 | 所有 MODULE + 全局背景 + 关键关注 | — |
| **迭代** | 聚焦 | **本轮变更 MODULE 清单**中的 MODULE + `## 关键关注` | PRD 中存在但不在清单中的 MODULE 仅做一致性检查；`影响范围 = 模块` 时复杂流程 Mermaid 可在变更 MODULE 内局部表达，不要求重画全局主流程 |

**本轮变更 MODULE 清单**（迭代需求在 Step 3 确认，写入 `ai-review.md`）：

1. **首选**：Step 3 脑暴澄清时产品确认的 MODULE 列表（如 `MODULE-2, MODULE-3`）
2. **次选**：`## 关键变更摘要` 中列出的 MODULE（按摘要中的模块名匹配 `MODULE-N`）
3. **兜底**：以上均缺失 → 对 PRD 内**所有 MODULE 全量深审**，并在 `ai-review.md` 注明「未提供变更清单，已降级为全量评审」

> MODULE 标题的 `[新增/修改]` **不用于**生成本清单；清单来源只能是 Step 3 确认或关键变更摘要。

**迭代模式轻审规则**：对「在 PRD 中出现但不在本轮变更清单」的 MODULE，只检查「本次改动是否与其现有描述冲突」；有冲突才展开为 P0/P1 问题项。

**评审范围说明**（写入 `ai-review.md` 开头）：

```markdown
## 评审范围
- 需求类型：<新增 / 迭代> | 影响范围：<页面 / 模块 / 流程>
- 本轮变更 MODULE 清单：<MODULE-2, MODULE-3>（迭代必填；来源：Step 3 确认 / 关键变更摘要 / 兜底全量）
- 深审：MODULE-x, MODULE-y, ## 关键关注
- 轻审：MODULE-z（一致性检查）
- 跳过：<无冲突的全局段落>
```

若 `开发速览` 未填写需求类型：Step 3 澄清时确认；仍缺失则默认**全量评审**并在 `ai-review.md` 注明。

## 二、阻断规则（P0）

命中任一条即阻断 confirmed：

### 内容质量（5 条）

1. 缺少明确目标或问题定义（只写“做什么”，没写“为什么做”）
2. 深审范围内关键 MODULE 缺少可测试验收标准
3. 范围边界冲突或明显自相矛盾
4. 深审范围内关键流程不闭环（成功/失败/异常路径缺失且业务需要）
5. 存在原型引用但路径或锚点无效（有原型需求场景）

### 可读性结构（3 条）

6. 缺少非 AI 区块的「关键关注（必填）」或「回归范围（必填）」模块，或该信息仅出现在 AI Review 结论区
7. 深审范围内命中复杂流程条件（存在分支逻辑 / 流程步骤 >= 5）但未提供 Mermaid 流程图（迭代+模块级影响时允许在变更 MODULE 内局部图示）
8. 存在大段文字违规：连续正文超过 6 行，或虽未超 6 行但主观可读性差

### 用户场景（P0，仅深审 MODULE）

9. 深审范围内核心业务 MODULE 的「需求描述」完全缺少目标用户与使用场景（不知道谁在用、什么情况下用）

## 三、建议项（P1/P2，不阻断 confirmed）

### P1（应修复，扣分并全量列出）

- 有主场景但描述含糊，PM/开发仍可能理解分歧
- 业务需要但缺少边缘/异常场景（可与「边界与异常」块互补）
- 回归范围仅写「无回归」等歧义表述，未写明需回归项或不纳入回归的范围与原因
- 表述、引用、局部可读性可改进但不触发 P0

### P2（可选优化，最多列 3 条）

- 体验优化、表述润色、非关键引用增强

## 四、用户场景透镜（深审 MODULE 必查）

每个**深审** MODULE 的「1) 需求描述」须覆盖：

| 要素 | 要求 | 缺失处理 |
|------|------|----------|
| 目标用户 | 一句话（角色/权限/使用前提） | 完全缺失 → P0（规则 9） |
| 核心场景 | 主路径：触发条件 → 用户操作 → 预期结果 | 含糊 → P1 |
| 边缘/异常场景 | 至少 1 条（业务需要时；可与块 4 合并） | 缺失 → P1 |

## 五、评分模型（0-100）

| 维度 | 分值 | 说明 |
|------|------|------|
| 目标与用户场景 | 25 | 含目标用户、核心场景、边缘/异常场景（仅评深审 MODULE） |
| 范围与边界完整性 | 20 | |
| MODULE 结构完整性 | 20 | |
| 验收标准可测试性 | 20 | |
| 可读性与引用质量 | 15 | |

说明：

- 来源链接缺失不计入评分，不作为阻断项
- P1 项参考扣分：-8；P2 参考扣分：-3（写入各问题项，总分不低于 0）

## 六、输出格式

### 写入 `prototypes/ai-review.md`

```markdown
## 评审范围
（见第一节模板）

## 可开工结论
可开工 / 建议完善后开工 / 不可开工

## 总分
XX/100

## 维度评分
- 目标与用户场景：X/25
- ...

## 问题项

### [P0] <类别> — <位置>
- **问题**：...
- **建议**：...
- **可粘贴示例**：（可直接写入 prd.md 的改写片段）
- **评分影响**：阻断

### [P1] <类别> — MODULE-2 / 变更点
- **问题**：...
- **建议**：...
- **可粘贴示例**：...
- **评分影响**：-8（<维度名>）

## P2 优化建议（最多 3 条）
...
```

**问题项格式硬规则**：

- 位置必填：`MODULE-N / <块名>`（需求描述、变更点、验收标准、边界与异常、引用）或 `## 关键关注` 或 `## 开发速览`
- 类别必填：`用户场景 | 功能逻辑 | 边界范围 | 可读性 | 原型展示` 五选一
- P0/P1 **全量列出**；P2 最多 3 条
- 每条 P0/P1 须含**可粘贴示例**（一段可直接贴回 prd.md 的文字）

### 写入 `prd.md`

1. 可开工结论（仅结论）
2. 评审时间
3. 详细记录路径：`prototypes/ai-review.md`

## 七、可读性硬约束

- 连续正文超过 6 行视为大段文字违规；未超 6 行但可读性差同样可判定违规
- 每份 PRD 须含 `## 关键关注（必填）` 与 `## 回归范围（必填）`；回归范围禁止仅写「无回归」
- 验收标准使用 checklist；MODULE 标题带 `[新增/修改]`（表示本次变更模块，不用于决定评审范围）
- 复杂流程（存在分支逻辑，或流程步骤 >= 5）必须包含 Mermaid 流程图
- 富文本必须“适量”：禁止无意义堆叠 callout/流程图；每个 MODULE 建议最多 1 个 callout
- 顶层摘要可选，但若存在必须简洁
- 无原型 MODULE 在引用中写明“无原型（原因）”
