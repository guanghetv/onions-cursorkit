# PRD AI Review Rubric

用于 `/pm-spec` 的 AI 评审标准：高风险阻断 + 评分反馈。

落盘分层：

- 详细评审记录（评分、维度说明、改进建议）写入 `prototypes/ai-review.md`
- `prd.md` 仅保留“可开工结论”

## 一、阻断规则（5 条）

命中任一条即阻断 confirmed：

1. 缺少明确目标或问题定义（只写“做什么”，没写“为什么做”）
2. 关键 MODULE 缺少可测试验收标准
3. 范围边界冲突或明显自相矛盾
4. 关键流程不闭环（成功/失败/异常路径缺失且业务需要）
5. 存在原型引用但路径或锚点无效（有原型需求场景）

## 二、评分模型（0-100）

建议维度：

- 目标清晰度（20）
- 范围与边界完整性（20）
- MODULE 结构完整性（20）
- 验收标准可测试性（25）
- 可读性与引用质量（15）

说明：

- 来源链接缺失不计入评分，不作为阻断项

## 三、输出格式

写入 `prototypes/ai-review.md` 的格式：

1. 可开工结论：可开工 / 建议完善后开工 / 不可开工
2. 总分：`XX/100`
3. 高风险项（如有）
4. 最多 3 条高收益改进建议（每条含可直接改写的示例）

写入 `prd.md` 的格式：

1. 可开工结论（仅结论）
2. 评审时间
3. 详细记录路径：`prototypes/ai-review.md`

## 四、可读性硬约束

- 避免大段文字，优先使用列表、表格、callout、流程图
- 顶层摘要可选，但若存在必须简洁
- 无原型 MODULE 在引用中写明“无原型（原因）”
