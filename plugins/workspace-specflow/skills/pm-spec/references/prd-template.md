# prd.md 模板

正文写法以 `plugins/workspace-specflow/references/产品组PRD写作规范.md` 为准（来源 [产品组 PRD 写作规范 V1.0](https://guanghe.feishu.cn/docx/Cqtqd9BxJoUYAFxbXFocp2qYnWd)）。

`prd.md` 是持续更新的工作稿。下游在第一次 `/prd-publish` 成功后读基线快照；漂移期间不把未发布正文当成已发布需求。章节定位以 **语义 unit + 标题关键词** 为准（见 `prd-feishu-sync/references/chapter-map.md`），序号仅展示/兼容。

旧飞书七章模板链接仅作兼容参考：https://guanghe.feishu.cn/docx/S38Id4fxAofdz8xsWCVcRkHjnHg。新文档以写作规范的组织方式为准，不为凑齐旧七章增加空章节。

## 结构约束

- **组织**：标题与版本 → 背景与目标 → 本次范围 → 需求详情 → 关联材料与待确认项 → 数据观察与发布约束（按需）。
- **背景与目标保留**：本地与飞书都保留。不再做「9 稿删背景/价值」。
- **不单设验收章**：MODULE 详细说明写规则、状态和异常。不把同一规则再写成验收 checklist。
- **不要求套用**「功能说明／交互说明／补充规则／验收标准」四段式。
- **工作区补充**：有复杂协作或回归风险时保留「关键关注」「回归范围」。没有内容时不硬凑空章。
- **Feature / MODULE**：多模块时可用 Feature 清单对齐 MODULE。单模块小需求可直接写需求详情。
- **原型**：`prototypes/` 引用与 MODULE 锚点保留；无原型时写明原因。
- **序号**：不得为补洞重排「关键关注 / 回归」或整段前移四～七。

## 完整结构

小需求可裁剪空章节。大需求按模块展开。

## 要点

- 写法服从写作规范；旧七章标题只是兼容外壳。
- PM 姓名填版本表 **PM** 列；Agent 不覆盖已有值。
- 版本表只在 `/prd-publish` 成功后追加，版本号填追加前的 `R1`。
- Feature 的 MODULE 列与需求详情的 `MODULE-N` 一一对应。
- 用户未明确保留时，正文不应残留未决议的 `[待定]` / `[待交互确认]`。
- 连续裸段落 >6 行时，`/prd-check` 只告警不硬拦。`push` 不下这个结论。
- 检查明细写 `prototypes/prd-check-YYYY-MM-DD.md`；基线发布时把结论摘要写入版本表变更内容。
