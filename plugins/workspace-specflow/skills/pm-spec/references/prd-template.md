# prd.md 模板

prd.md 经历两个阶段：产品撰写（自由格式）→ `/pm-spec` 增强（MODULE 结构化）。

## 增强后完整结构

```markdown
# <需求标题>

> 来源: <飞书文档链接>
> 确认时间: YYYY-MM-DD

## 需求背景

（产品原始内容，保留不变）

## 功能模块

### MODULE-1: <模块名称>
**优先级**: P0/P1/P2
**描述**: （基于产品原文提炼）
**用户故事**:
- 作为<角色>，我希望<行为>，以便<价值>
**验收标准**:
- [ ] 标准1
- [ ] 标准2
**业务规则**:
- 规则1
- 规则2

### MODULE-2: <模块名称>
...

## 全局约束

（跨模块共享的约束条件：兼容性、性能、安全、数据迁移等）

## 名词解释

（业务术语定义，确保产品/开发/测试理解一致）
```

## 要点

- 保留产品原始内容（需求背景、功能描述等），在其上叠加 MODULE 结构
- 简单需求可只有一个 MODULE，但仍遵循相同结构
- MODULE ID 是稳定的引用锚点，开发和测试通过 MODULE ID 定位内容
