# PRD AI Review Rubric（5稿）

用于 `/pm-spec-5` 的轻量 AI 评审：面向**交互评审会**，不触发下游开工门禁。

落盘分层：

- 详细评审记录写入 `prototypes/ai-review-v5.md`
- `prd.md` 在 **二、版本及进度跟踪** 对应行记：`AI Review: 可进入交互评审`（或建议补充后进入 / 暂不建议）

## 一、评审范围

读取 `## 一、需求概述` 开发速览中的需求类型与影响范围。5稿默认对**所有已写出 MODULE** 做结构完整性检查，对灰区与待定项做清单化，不要求验收标准完整。

## 二、阻断规则（P0，5稿）

1. 完全缺少需求概述或「背景」小节（标题含「背景」、不知为何做；按语义定位，不认死序号）
2. 第四章 Feature List 与第五章 MODULE 严重不对齐（MODULE 列缺失或无法对应）
3. 完全缺少「关键关注」小节（无任何风险/开放问题记录；按标题关键词定位）

**不阻断**（5稿允许）：

- `[待定]` / `[待交互确认]` 标记
- 验收标准写「待交互后补充」
- 「关键关注」中含开放问题
- 复杂流程暂无 Mermaid（建议在 P1 提醒）
- 大段文字 / MODULE 说明偏长（仅告警，见 P1）

## 三、建议项（P1/P2）

### P1

- **可读性告警（不阻断，必做）**：扫描契约区裸段落连续正文 >6 行、MODULE「说明」整格纯文字墙  
  - **本地报告** `prototypes/ai-review-v5.md` 必须含「## 可读性告警」：逐条位置 + 拆分建议  
  - **飞书**（已绑定 `feishu.doc_token` 时）：更新 `prd-sync:readability:v1` 为橙色**摘要**（约 N 处 + 报告路径），**不要**在飞书列明细  
  - **不得**因此给「暂不建议进入交互评审」
- MODULE 拆分可能过大或过小，建议调整
- 待定项过多（>5 处）建议先收敛范围再进交互评审
- 缺少图示引用但有原型场景
- 开发速览未填需求类型/影响范围

### P2（最多 3 条）

- 表述润色、Feature List 优先级建议

## 四、结论措辞

| 结论 | 含义 |
|------|------|
| **可进入交互评审** | 结构达标，待定项已清单化 |
| **建议补充后进入交互评审** | 有 P1 项但不阻断，建议先补再开会 |
| **暂不建议进入交互评审** | 命中 P0 或范围严重不清 |

## 五、5稿确认后 Agent 动作

1. **二、版本表** 追加行：`5-n`、当天日期、变更摘要、待定项计数、`snapshots/prd-v5-*.md` 路径
2. 复制 `prd.md` → `snapshots/prd-v5-<YYYY-MM-DD>.md`
3. 更新 metadata：`prd.v5.status = confirmed`，`prd.stage = v5_confirmed`，`prd.v5.snapshot`
4. **不** 设置 `prd.status = confirmed`

## 六、位置锚点

同 9稿 rubric：`## 一、需求概述`、`### 3.3`、`## 五、需求详情说明 / MODULE-N / 说明列`

## 七、报告中的可读性章节（必含）

`prototypes/ai-review-v5.md` 须含：

```markdown
## 可读性告警
无 / 共 N 处（不阻断）
- <位置>：… — 建议…
```

飞书只写摘要 + 本报告路径，不复制上列明细。
