# AICR 提交门禁实施计划

## 1. 明确流程职责

- 更新 `rules/onion-sdd.mdc`，定义 AICR 的触发条件、暂存区基线、降级和复审规则。
- 更新 `full-change`，保留 `trellis-check` 的工程质量职责，并将提交 diff 审查引用统一规则。
- 更新 `auto-flow`，保留 `diff-review` 自检，禁止其自动暂存或调用 AICR。

验证点：检查三处均明确区分实现后质量检查、自动流程自检和提交前审查。

## 2. 同步使用文档

- 更新 README、USAGE 和飞书同步使用文档的 Commit review 说明。

验证点：搜索所有提交前审查表述，确认无冲突的旧流程。

## 3. 质量检查

- 检查修改文档为中文正文，路径和命令保持原文。
- 运行 Markdown/链接的可用检查；对提交门禁关键词进行静态检索。
- 走读有 AICR 与无 AICR 的两条流程，确认 `/onsf-auto` 不执行 Git 暂存或提交动作。

验证点：相关文档、规则和技能均有一致的正常及降级流程。
